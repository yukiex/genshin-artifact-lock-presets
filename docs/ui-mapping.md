# UI ↔ YAML Mapping (Lock Assist)
**目的**：原神の「自動ロック（ロックアシスト）」UIのチェック項目を、このリポジトリの **YAML プリセット**に正しく落とし込むための対応表と設計指針。

> 前提
> - UIは**サブステータスに対して「いずれかN個以上」**の条件を指定できる  
> - **メインステータスを必須にはできない**（→ 可能なら“許可フィルタ”として `main_allowed` を使い誤ロックを軽減）  
> - スロット：`flower`, `plume`, `sands`, `goblet`, `circlet`

## 2. 基本マッピング（サブステの指定）
UIの「追加するサブステータス」と「いずれかN個以上」は、YAMLでは下記に対応します。

```yaml
substats_required_any_of: [CR, CD, ER, EM]
substats_required_min: 2
substats_required_all_of: [ER, EM]
```

`substats_required_all_of` は UI で黄色表示される「必須ステータス」を 1 つも欠かさず含めるためのフィールド。Moonweaver 推奨設定のように ER/EM を両方要求するケースで利用する。

### チェックと☆の違い

| UI の状態 | 意味 | YAML |
| --- | --- | --- |
| 未選択 | 候補に含めない | `substats_required_any_of` に含めない |
| チェックあり・☆は灰色 | 個数条件を満たす候補 | `substats_required_any_of` に含める |
| チェックあり・☆は黄色 | 候補に含め、さらに必須にする | 上記に加え `substats_required_all_of` に含める |

黄色☆は優先順位やサブステの伸び回数ではなく、必須条件を指定する。
候補の個数条件と必須条件は両方満たす必要があり、必須の項目も候補の個数に数える。

2026-10-18 のユーザー提供画像（紅血の証・設定2・杯・追加ステータス）では、
会心率と会心ダメージが選択済み、会心率のみ黄色☆、個数は1個だった。
この画面状態を表すと次のようになる。

```yaml
substats_required_any_of: [CR, CD]
substats_required_min: 1
substats_required_all_of: [CR]
```

- 会心率のみ: 条件を満たす。
- 会心ダメージのみ: 個数は満たすが、必須の会心率がないため対象外。
- 会心率と会心ダメージの両方: 条件を満たす。

これは独自設定を操作中の画面で、ゲーム内推奨設定の証跡ではない。
保存や適用結果もこの画像だけでは確認できない。元画像は UID を含むため保存していない。

### ルールを作る・入力する際の確認

- 部位ごとに「候補」「いずれかN個」「必須（黄色☆）」をセットで記載する。
- `substats_required_all_of: []` は「黄色☆なし」。設定時は以前の黄色☆を解除する。
- 必須を設定する場合は理由を調査メモに残す。必須なしも判断結果として明記する。
- 必須項目は候補の部分集合にし、個数の閾値は必須項目数以上にする。
- メインと同じサブステは付かない。例: 会心率冠に `CR` 必須、熟知時計に `EM` 必須を指定しない。
- 共通のルールで `CR` と `CD` の「どちらか必須」を両方黄色☆で表現しない。両方必須になってしまう。
